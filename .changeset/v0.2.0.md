v0.2.0 merges upstream Kilo CLI v7.3.63 into the ResoftCode
distribution. This is the first sync that adopts the upstream
release tooling (Kilo `7.3.x` line) on top of v0.1.5, and pulls in
the upstream changes between v7.3.22 and v7.3.63 across
providers, sessions, prompts, and CLI commands.

What changed since v0.1.5:

- **Upstream Kilo v7.3.63** — Full rebase onto `Kilo-Org/kilocode`
  tag `v7.3.63` (commit `82da283d`). The merge runs through
  `script/upstream/merge.ts` with auto-resolution (Keep ours,
  i18n transform, branding transform, mergiraf). Resoft-specific
  changes (resoft-data default mode, Provider presets, brand,
  starter) are preserved via the existing `kilocode_change` /
  `resoft_change` marker system.
- **Resoft-Data defaults preserved** — `resoft-data` remains the
  product default agent (`packages/opencode/src/agent/agent.ts`)
  with the disable-then-fallback chain to `code` and `plan`.
- **Resoft Provider presets preserved** — `packages/opencode/src/
  provider/provider.ts` still wires the seven Resoft presets
  (`kilocode/resoft/starter.ts`) and the custom-provider loader.
- **Build version source unchanged** — v0.1.5's fix where
  `script/build.ts` reads `pkg.version` directly (rather than
  `@opencode-ai/script`'s upstream Kilo version) carries forward.
- **Internal version markers** — `.resoft-version` baseline note
  updated from `7.3.22` → `7.3.63`; `package.json` version
  bumped from `0.1.5` → `0.2.0`.

Notes for users:

- No user-facing command changes beyond what v7.3.63 itself
  introduced upstream; Resoft brand strings (`Brand.product`,
  `Brand.cliName`, etc.) still surface in CLI output and
  documentation.
- If you previously installed v0.1.x, run
  `npm update -g @chinaresoft/resoftcode` to pick up v0.2.0.
- Post-install reminders: `resoftcode --version` reports
  `0.2.0`; CLI defaults to the `resoft-data` agent unless
  overridden in `kilo.jsonc`.

Known runtime gaps (not blocking v0.2.0 release, tracked in
follow-up):

- A handful of integration tests (DOCX read, BackgroundProcess
  port inference, session-export worker e2e, indexing config
  precedence) fail under full-suite runs but pass when run in
  isolation. These are pre-existing isolation issues inherited
  from the upstream test runner, not regressions introduced by
  the merge.
