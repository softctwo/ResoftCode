Patch v0.1.5 fixes the local build and packaging path so the
generated Resoft binary version matches the Resoft package version.

What changed since v0.1.4:

- **Build version source**: `script/build.ts` now uses the
  Resoft package version from `packages/opencode/package.json`
  when embedding `KILO_VERSION`, writing platform package metadata,
  and naming release upload targets. This prevents the Resoft
  binary from reporting an upstream-derived Kilo version.
- **Publish asset metadata**: `script/publish.ts --pack-only`
  and future publish runs now derive release asset URLs and package
  metadata from the built Resoft package version.
- **Local install confidence**: packaging tests now lock the
  Resoft version contract and update the Resoft branding/header
  assertions used by the local test suite.

Upgrade after publish:

```sh
npm update -g @chinaresoft/resoftcode
resoftcode --version  # 0.1.5
resoftcode -m deepseek/deepseek-v4-pro
```
