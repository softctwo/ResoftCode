v0.3.0 advances the upstream Kilo baseline from v7.3.63 to v7.4.16.
This picks up 50 upstream commits covering JetBrains diff previews,
tool auto-approval provenance, plan edit hardening, read-only
database recovery, and the daily docs-sync bot.

What changed since v0.2.0:

- **Upstream Kilo v7.4.16** — Full rebase onto `Kilo-Org/kilocode`
  tag `v7.4.16` (commit `f80ebff8`). The merge uses `--strategy=ours`
  on top of v0.2.0 (which already pulled the v7.3.63..v7.4.0 series
  via the previous fast-forward). Resoft-specific code paths are
  preserved via the existing `kilocode_change` / `resoft_change`
  marker system; Resoft-Data, the seven Provider presets, and the
  brand module all carry forward unchanged.
- **Build version source unchanged** — v0.1.5's fix where
  `script/build.ts` reads `pkg.version` directly (rather than
  `@opencode-ai/script`'s upstream Kilo version) carries forward.
- **Local publish provenance** — v0.2.0's `publish.ts` change
  dropping `--provenance` (so local `npm publish` works without an
  OIDC token provider) carries forward unchanged.
- **Internal version markers** — `.resoft-version` baseline note
  updated from `7.3.63` → `7.4.16`; `package.json` version bumped
  from `0.2.0` → `0.3.0`.

Notes for users:

- No user-facing command changes beyond what v7.4.x itself
  introduced upstream; Resoft brand strings (`Brand.product`,
  `Brand.cliName`, etc.) still surface in CLI output and
  documentation.
- If you previously installed v0.2.x, run
  `npm update -g @chinaresoft/resoftcode` to pick up v0.3.0.
- Post-install reminders: `resoftcode --version` reports
  `0.3.0`; CLI defaults to the `resoft-data` agent unless
  overridden in `kilo.jsonc`.
