Patch v0.1.1 fixes the model context windows on the V1 starter
presets and adds CLI overrides for the active preset's
`context` and `output` window.

What changed since 0.1.0:

- **DeepSeek preset**: `context` raised from 128000 to 1000000
  tokens (DeepSeek V4 Pro is a 1M-token model; the 128K default
  triggered premature conversation compaction during real
  regulatory-reporting runs). `output` raised from 16000 to
  32000.
- **Qwen preset** (Qwen3-Coder-Plus on DashScope): `context`
  raised from 128000 to 256000 tokens (matches the published
  DashScope window). `output` raised from 16000 to 32000.
- **Ollama preset** (qwen2.5-coder:32b): `output` corrected from
  8000 to 8192 to match the model's real max output.
- **CLI overrides** — `resoft init` gains `--context <N>` and
  `--output <N>` flags that flow through `ProviderInput` to
  `resolveProvider`, so an operator can pin the active preset to
  the actual window of their plan without editing source.
  Example:
  ```
  resoft init --provider deepseek --context 64000 --dir ./demo
  ```
- **init log** now prints the resolved `context` / `output` and
  points the operator at the override flag, so a stale preset
  shows up on first run instead of biting in the middle of a
  long-running report.

The other five presets (resoft / openai / moonshot / zhipu)
keep their existing context values — those windows are still
accurate for the models currently shipped.

Upgrade:

```sh
npm update -g @chinaresoft/resoftcode
resoftcode --version  # 0.1.1
resoftcode resoft init --provider deepseek --dir ./reg-reporting
# kilo.jsonc now advertises 1000000 tokens of context for deepseek
```
